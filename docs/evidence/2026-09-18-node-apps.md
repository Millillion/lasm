# Ordinary Lean applications on Node: local evidence

Recorded on 2026-09-18 for `0.1.0-experimental.3`, native Linux x64,
Node 24.13.1, and Lean 4.32.0 (`8c9756b28d64dab099da31a4c09229a9e6a2ef35`).
Runtime/example changes are in local commits `55a73d6`, `e08c43f`, `029f101`,
and `66884ff`. No remote or publication was used.

## Implemented application

`examples/lean-server` is an ordinary Lake project. `Main.lean`, `App/Server.lean`,
and `App/Model.lean` implement the main function, HTTP routes, validation, state,
and filesystem persistence. They import standard Lean libraries and contain no
Lasm-specific imports, extern declarations, export annotations, or API wrappers.
The same source builds as a native Lean executable and as a Node/Wasm application.

The application exercises JSON CRUD with revision conflicts, concurrent mutation,
binary and chunked bodies, server-sent events, request limits, persistent restarts,
and graceful shutdown. Node supplies filesystem/TCP/timer primitives; Lean's
standard HTTP implementation and application handlers execute in Wasm.

Commands for the final source checks:

```sh
node --test --test-concurrency=1 test/runtime.test.mjs test/io.test.mjs test/node-host.test.mjs test/node-platform.test.mjs
node --test --test-name-pattern='ordinary console' test/standard-io.test.mjs
node --test --test-name-pattern='standalone files' test/standard-io.test.mjs
npm run test:lean-server
npm run test:hosts

```

The three controlled platform configurations check Lean's Windows/macOS flags,
path joining/parent/drive handling, UTC dates, and Wasm's 32-bit pointer width.
They do not execute Windows or macOS filesystems, tools, or sockets.

## Installed package acceptance

All four final package tests passed: npm, pnpm, Yarn, and the ordinary Lean HTTP
application installed into a separate npm project. The exact package identity,
platform, sizes, timings, and completed checks are recorded in
[the release report](2026-09-18-node-apps-release.json).

The tested local candidate is `lasm-compiler-0.1.0-experimental.3.tgz`, SHA-256
`3d22c9a98fa4ca48509df23a86f97656a880bbe9e2dbb83e1a31fb1d960df01d`.
It is 58,959,794 bytes compressed and 243,805,010 bytes installed. The archive is
an ignored local build under `.work/release`, not a published registry package.

Installations used empty package-manager caches and disabled network access for
package resolution. Consumer builds used the installed SDK, Node, and Lean's
bundled Clang/LLD; there was no separate C SDK or Zig in their compiler paths.
The server checks include actual HTTP dates, Unicode persistence, streaming,
shutdown, and a second run after deleting `node_modules`. Generated output needs
Node alone. Temporary projects included spaces and Japanese characters in paths.

```sh
npm run package:release
npm run test:release
```

## Boundaries of this evidence

The server's keep-alive workload has a separate memory-plateau test. Repeated new
connections retain accept-loop task continuations until shutdown; this is not
a proof of stable memory for a long-running server. Tests verify that sockets and
timers are released after disconnects, and fibers, pending task registrations,
and host resources reach zero after graceful shutdown. External abort is tested
separately and discards the whole instance.

Native Linux ARM64, macOS Intel/ARM64, and Windows x64/ARM64 runs are still pending.
The prepared GitHub Actions workflow has not run. All IO coverage and semantic
gaps remain listed with empty checkboxes in [IO_LIMITATIONS.md](../../IO_LIMITATIONS.md).
