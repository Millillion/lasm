## Decisions

### A26 Workers `env`: the program declares `Env`, the handlers receive it typed

- **Decision** (Jordan, 2026-11-16, option (b)): the program declares its bindings as
  a structure with `deriving FromJS`, and every handler gets it typed. The generated
  `ofFn` and `ofSyncFn` of `ExportedHandlerFetchHandler`,
  `ExportedHandlerScheduledHandler` and `ExportedHandlerQueueHandler` take
  `{Env : Type} [FromJS Env]`, and so does `Lasm.JS.Cloudflare.env` (`env` of
  `cloudflare:workers`). The handle types themselves stay unparameterized: they are
  JavaScript functions.

  ```lean
  structure Env where
    KV : KVNamespace     -- [[kv_namespaces]] binding = "KV"
    DB : D1Database      -- [[d1_databases]] binding = "DB"
    GREETING : String    -- [vars]
    deriving FromJS

  let fetch ← ExportedHandlerFetchHandler.ofFn fun request (env : Env) ctx => do
    let hits := ((← env.KV.get "hits").bind String.toNat?).getD 0
    …
  let e : Env ← Lasm.JS.Cloudflare.env
  ```
- **How it is generated:** the tier's `typeParameters` (`cloudflare-tier3.mjs`) names
  `Env`. The lowering writes the type as `typedef any Cloudflare_Env` marked
  `[LasmTypeParameter="Env"]`, and `generate-web.mjs` makes such a typedef a Lean type
  parameter, decoded by `Lasm.JS.Cloudflare.Support.declared`. That function reads a
  plain object as data and first copies an object that is not plain (a proxy) with
  `Object.entries`. A missing binding fails with an error naming the field.
- **Why:** it is what the platform expects. `ExportedHandler<Env>` is generic, and a
  TypeScript Worker declares `interface Env`. Typed fields replace per-request
  `readField KVNamespace env "KV"` lookups that fail only at run time.
- **Alternatives:** (a) `Data` and `readField` (the previous shape; still possible,
  since `Data` is a valid `Env`); (c) generated accessors per binding name (Lasm cannot
  know the program's names).
- **Breaking:** a handler that annotated `env : Data` keeps working. A handler that
  left `env` unannotated and used `readField` on it must now say `(env : Data)` or
  declare an `Env`.
- **Where:** PR #216, released in 0.9.0. **Status:** pending sign-off.

### A27 `Lasm.JS.Async.toPromise`

- **Decision:** a new core function, `Lasm.JS.Async.toPromise [ToJS α] : Async α → IO Value`.
  It starts the computation at once as a Lean task, holding no Lean thread while it
  awaits, and returns a JavaScript promise of `toJS` of its result. The promise
  rejects with an `Error` if the computation throws.

  ```lean
  ctx.waitUntil (← Async.toPromise (env.KV.put "seen" (.domString "1")))
  state.waitUntil (← Async.toPromise (flushLog env))
  ```
- **Why:** `ExecutionContext.waitUntil`, `DurableObjectState.waitUntil` and any API
  typed `Promise<T>` take a promise of work already running. Programs had to write the
  `Function.ofFn` / `call` pair by hand. `blockConcurrencyWhile` needs nothing new:
  it takes a callback, which the generated `DurableObjectStateBlockConcurrencyWhileCallback.ofFn` makes.
- **Alternatives:** leave it to programs (the previous state); type the generated
  `Promise` parameters as `Async α` (it hides a promise that already exists, such as one
  returned by another binding).
- **Where:** PR #216, released in 0.9.0; in Lasm.JS core, agreed with the 0.6 stream through
  main. **Status:** pending sign-off.

### A28 Durable Objects stay a JavaScript class in the project

- **Decision:** a Durable Object is the JavaScript class that the Worker's main module
  exports (`export class Counter extends DurableObject`), a few lines in the project's
  `index.mjs` whose methods call Lean functions published on `globalThis`. Every
  Durable Object API (namespaces, ids, stubs, `DurableObjectState`, storage,
  transactions, alarms) is generated and usable from Lean today. This support does
  not wait for `Lasm.JS.Class.define` (A6).
- **Why:** the class is what Workers natively expects. When this was decided Lean could not define JavaScript
  classes, and a Lasm-generated class shim would be the kind of indirection that
  Jordan's rule excludes. `Lasm.JS.Class.define` (A6.2) is deleted: classes are
  JavaScript in the project (docs/JS_BINDINGS.md, "JavaScript classes"), and #379 explores
  typed classes generated at build time.
- **Alternatives:** block Durable Objects on A6; have Lasm's entry generate the class
  from a naming convention (context-dependent).
- **Where:** PR #216, released in 0.9.0; docs/JS_BINDINGS.md, "Durable Objects: a class in
  JavaScript"; test/fixtures/js-cloudflare/index.mjs. **Status:** pending sign-off.

### A29 Lasm.JS.Cloudflare merged, with the shared rules applied afterwards

- **Decision:** PR #216 merges with its mapping (documented in docs/JS_BINDINGS.md,
  "How the declarations become Lean"). Its shape choices: string-literal overloads become
  named functions (`getJson`, `getArrayBuffer`, `getStream`); same-name overloads

  in 0.9.0 (#301, then #320 for Cloudflare's whole surface; 0.5-14, 0.5-15, 0.5-17).
- **Where:** PR #216, released in 0.9.0. **Status:** pending sign-off.

- **Decision:** the generated `workers/worker.mjs` exports `scheduled`, `queue`,

### 0.5-11 Lasm.JS.Cloudflare generates every declaration of Cloudflare's own

- **Decision** (Jordan, 2026-11-16: "generated sources as is"): every declaration of
  `@cloudflare/workers-types` that is Cloudflare's own is generated. That is 838
  declarations: KV, D1, R2, Durable Objects (with SQLite storage, facets and
  WebSocket hibernation), Queues, Workers AI (every model's inputs and outputs), AI
  Gateway, AI Search, AutoRAG, Agent memory, Vectorize, Hyperdrive, Images and Media,
  Email, Tail, Trace and TailStream, Containers, Workflows, service bindings and RPC,
  Worker loaders, dispatch namespaces, Browser Rendering, Analytics Engine, Stream,
  HTMLRewriter, the `cf` properties, rate limiting, Secrets Store, Artifacts,
  Flagship and Pipelines. There is no hand-picked selection and no per-member decision
  table. The rule that tells Cloudflare's declarations from the web platform's is
  mechanical (`scripts/bindings/cloudflare-classify.mjs`):
  - a name that the web platform's WebIDL (the pinned `@webref/idl`) defines is
    Lasm.JS.Web's, and so is a global of `WindowOrWorkerGlobalScope`;
  - workerd's own names for a web type's dictionaries (`CustomEventCustomEventInit`),
    used only by web declarations, are Lasm.JS.Web's too;
  - Node's globals are Lasm.JS.Node's;
  - every other declaration is generated.

  The web types that workers-types re-declares are mapped to Lasm.JS.Web's in one
  table (`webTypeName` in `cloudflare-tier3.mjs`), so changing Lasm.JS.Web's layout
  changes one line. The Cache API (`Cache`, `CacheStorage`) stays in
  Lasm.JS.Cloudflare.Cache until Lasm.JS.Web generates it.
- **Where:** PR #320, released in 0.9.0. **Status:** pending sign-off.

### 0.5-12 What is not generated, by class

- **Symbol-keyed members** (`[Symbol.iterator]()`, `[Symbol.dispose]()`, Rpc's brand
  symbols) are the JavaScript protocols. They are reached with `Lasm.JS.Value.get` and a
  Symbol key (A47).
- **Members whose key is not an identifier** (the `"@cf/…"` keys of `AiModels`, a map of
  model names that exists only in the types) are read through `Data`.
- **Private and protected class members** are not the class's API.
- **Constructors of abstract classes** (`WorkerEntrypoint`, `DurableObject`,
  `WorkflowEntrypoint` of `cloudflare:workers`) are subclassed, not constructed (A28).
- **Index signatures beside named members** (`[key: string]: unknown`): the named members
  are generated, and other keys are read and written through `Data`.
- **Type-level helpers** (generic type aliases such as `Rpc.Stub<T>`, conditional and
  mapped types) are lowered where they are used. A conditional type, `typeof C`, or a
  generic indexed access such as `AiModelList[Name]["inputs"]` reads as `Data`.

  Each exclusion is listed with its reason at the top of `cloudflare.idl`.
- **Status:** pending sign-off.

### 0.5-13 Modules by area

- **Decision:** each declaration goes to the module of its area (`areas` in
  `cloudflare-tier3.mjs`: `Kv`, `D1`, `R2`, `Queues`, `DurableObjects`, `Ai`, `Vectorize`,
  …). Areas whose types use each other's become one module, and the modules are ordered
  by use (written to `cloudflare-modules.json`). Each handler type is in its event's
  module: the queue handler in `Queues`, the tail handlers in `Tail`, the email handler
  in `Email`. `ExportedHandler`, which names every handler, is in `Handlers`. The fetch
  handler and `ExecutionContext` are in `Workers`, which imports no other Cloudflare
  module. A Worker that uses KV and D1 imports `Lasm.JS.Cloudflare.Kv`, `.D1` and
  `.Workers`, and links nothing else. (The umbrella module this entry first had is
  dropped: 0.5-16.)
- **Status:** pending sign-off.

### 0.5-14 Generated-binding rules for the full surface (A9 refinements, shared generator)

- **Overloads with the same parameter names:** the one with the fewest required
  arguments keeps the method's name; ties go to the shortest declaration. So
  `R2Bucket.get(key, options?)` keeps `get`, and the overload whose `onlyIf` is
  required gets the next name. Overloads with different parameter names keep the
  declaration's order, so `DurableObjectStorage.put(key, value)` stays `put`.
- **Names that would collide** follow Lasm.JS.Web's shared rule (#319): an overload of
  the same argument names and length adds all its argument types
  (`KVNamespace.getWithSequenceOfDOMStringKVNamespaceGetOptions`), and as a last resort
  its position. Train B (#319 + #320) replaced #320's own `…Of…` rule with that one,
  so the generator has one rule. Those that read badly are renamed in the shared
  override table (0.5-15, 0.5-17).
- **Members holding a class** (`Tracing.Span: typeof Span`) are named `SpanClass` in
  Lean.
- **Same shapes:** dictionaries and enumerations with the same members in one module
  are one type. Each later one is a Lean `abbrev` of the first: 667 abbrevs. Sharing
  never crosses modules, so it never adds an import.
- **Instances by direction of use:** a type gets `ToJS` where it flows into JavaScript
  and `FromJS` where it flows out. A type that no member names gets the direction its
  declarations give it: Workers AI's model inputs are written and its outputs read,
  from `run`'s `AiModelList[Name]["inputs"]` and `["postProcessedOutputs"]`. Otherwise
  it gets `ToJS`, so a program can pass it (`ExportedHandler` to `exportDefault`).
- **Generated modules** set `genInjectivity`, `genSizeOfSpec` and
  `compiler.extract_closed` off. These are proof-support lemmas and closed-term
  extraction, which no binding needs.
- **Status:** pending sign-off.

### 0.5-15 Overrides for Lasm.JS.Cloudflare's awkward overload names

- **Decision:** three entries in `scripts/bindings/overrides.json` (A9's override table,

    is `R2Bucket.putWithOnlyIf`: `put` with `onlyIf` required, whose result is `none`
    when the condition fails.
  - `D1PreparedStatement.rawWithAny` is `D1PreparedStatement.rawWithColumnNames`:
    `raw({ columnNames: true })`, whose first row is the column names.
- **Status:** pending sign-off.

### 0.5-16 No umbrella module; a small compiled core, the rest compiled on first import

- **Decision:** there is no `Lasm.JS.Cloudflare` module. A program imports the modules of
  the areas it uses (`import Lasm.JS.Cloudflare.Kv`, `.D1`, `.Workers`, …). With
  compilation on first import (0.3-6, `src/lazy-library.mjs`), an umbrella would make its
  first use compile every module. Lasm.JS.Web dropped its umbrella for the same reason.
  `Lasm.JS.Cloudflare.Support`, `.Kv`, `.D1` and `.Workers` ship compiled, a core closed
  under imports (about 4 MB of oleans). It covers what the apps and templates use: a fetch
  handler, `ExecutionContext`, the typed `Env`, KV and D1. Every other module, `Handlers`
  (`ExportedHandler`) and Workers AI included, compiles into the user's cache the first
  time it is imported. Workers AI's catalog takes about 25 s single-threaded.
- **Supersedes:** 0.5-13's umbrella (all modules but `Ai`).
- **Alternatives:** an umbrella compiled lazily (its first use would compile everything);
  shipping every module compiled (about 77 MB of oleans and 31 MB of C).
- **Status:** signed off by Jordan (2026-11-16).

### 0.5-17 Overrides for the Cloudflare overload names after Train B

- **Decision:** Train B (#319 + #320) keeps one shared overload-naming rule: all argument
  types, then the position. It names several Cloudflare overloads by their types
  (`KVNamespace.getWithSequenceOfDOMStringKVNamespaceGetOptions`,
  `Ai.runWithAnyAnyAiRunOptions`). Nineteen entries in `scripts/bindings/overrides.json`
  name them for what they do:
  - `KVNamespace`: several keys at once are `getMany`, `getManyText`, `getManyJson`,
    `getManyWithMetadata`, `getManyWithMetadataText` and `getManyWithMetadataJson`.
  - `Ai`: `run model inputs options?` is the common call (the model's outputs). The other
    forms are `runStream` (`stream: true`), `runWebSocket` (`websocket: true`),
    `runRawResponse` (`returnRawResponse: true`) and `runOtherModel` (a model the
    catalog does not list). Also `toMarkdownFile` and `toMarkdownFiles`.
  - `ToMarkdownService.transformMany`, for several documents.
  - `AiSearchInstance.chatCompletionsStream` and `AiSearchNamespace.chatCompletionsStream`
    (`stream: true`). `AiSearchNamespace.chatCompletions` is the plain response, as
    `AiSearchInstance`'s is.
  - `WorkflowStep.doWithDelayFunction` and `doWithStaticDelay`, by their config's kind of
    retry delay. `doWithConfig` and `do` are unchanged.
- **Why not a generator rule:** these overloads differ by a literal option
  (`stream: true`), by one array argument, or by a config type. The shared rule cannot
  say which one is the common call, and that is what the override table is for (A9).
- **Breaking:** none in practice: 0.9.0 (#336) shipped these names, and no release had the mechanical ones.
- **Where:** PR #336, released in 0.9.0.
- **Status:** pending sign-off.

### 0.5-18 Lasm.KV deleted

- **Decision** (Jordan, 2026-11-16): `Lasm.KV`, `Lasm.KV.Spec` and `Lasm.KV.Theorems` are
  deleted, and so is their wiring: the library module list, the proof check, the
  proof-axiom check, `library/PROOFS.md`'s six propositions about the memory store, and
  the Fastly bindings workflow's path. A program uses its platform's own store through
  that platform's generated binding:

  ```lean
  -- Cloudflare Workers: a binding of the program's Env (A26)
  structure Env where
    TODOS : KVNamespace
    deriving FromJS
  let v ← env.TODOS.get "state"
  env.TODOS.put "state" (.domString json)
  -- Deno, Deno Deploy (Lasm.JS.Deno.Kv)
  let kv ← openKv
  let e ← kv.get #[.domString "TODOS", .domString "state"]
  -- Fastly Compute (Lasm.Fastly.KvStore)
  let store ← (KvStore.open "TODOS" : IO _)
  ```
- **Why:** Lasm.KV picked a backend by where the program ran. On Workers, after #331, it
  silently fell back to memory, the context-dependent behaviour Jordan's rule excludes.
  Its interface was strings only (A40), and each platform's own store does more
  (metadata, TTLs, lists, atomic operations).
- **A missing store is an error, never memory:** a declared `Env` binding that is absent
  fails at the first read and names the field; the apps' Fastly stores fail, naming the
  store. Memory remains only where a platform has no store (Conduit on Vercel Edge),
  and there it is said so.
- **Migration:** see the release note (docs/release/0.10.0-notes.md). The
  fullstack template moved in #344; Conduit and Folio move with the apps PR.
- **Where:** PR #346, released in 0.10.0.
- **Status:** pending sign-off.

### 0.5-8 Ledger's Workers questions: compression and a cross-request lock

- **Brotli on Workers.** Workers compresses a response itself, following its
  `Content-Encoding` header (`encodeBody: "automatic"`, the default). A body that is
  already compressed would be compressed twice. The platform-native way is to send the
  body uncompressed and let Cloudflare negotiate and compress at the edge. Static files
  are served by Workers' `[assets]` before the Worker runs, and Cloudflare compresses
  those too. **Decision:** no Lasm API. On Workers, a program does not set
  `Content-Encoding` on its own responses. Ledger's embedded files there go out as
  identity, with no Brotli copy; on the other platforms they stay as they are. `encodeBody` is
  a Cloudflare member of the web `ResponseInit`, which Lasm.JS.Web owns (0.5-11). It is
  generated if 0.3's web types grow host extensions; nothing needs it now.
- **A cross-request lock on Workers.** A Worker cannot wait on another request's promise.
  The runtime cancels it ("Cannot perform I/O on behalf of a different request"), so an
  in-isolate semaphore cannot serialize requests, and an isolate is not the only one
  serving anyway. **Decision:** no Lasm lock. Serialize with the platform's own tools:
  - D1's `batch` is one transaction. Ledger and Porter commit with a version check inside
    it (optimistic concurrency, as they do now), which holds across isolates.
  - Where strict one-at-a-time is needed, use a Durable Object: one instance per key,
    single-threaded, with `state.blockConcurrencyWhile` for the critical section (A28,
    `DurableObjectStateBlockConcurrencyWhileCallback.ofFn`).
- **Why:** both are what Workers itself provides. A Lasm-level lock or compression
  layer would be a clever indirection that behaves differently by platform.
- **Where:** this entry. Ledger's change (no Brotli copy in its Workers build) is in
  Ledger's Stage 0 PR (#355). **Status:** pending sign-off.
