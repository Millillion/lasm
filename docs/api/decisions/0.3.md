## 0.3 `Lasm.JS.Web`

| Id | Surface | Current shape, with an example | Status |
| --- | --- | --- | --- |
| 0.3-1 | `Lasm.JS.Web` and `Lasm.JS.Web.*` (tier 1, the WinterTC Minimum Common Web API) | Generated by `scripts/bindings/generate-web.mjs` from `@webref/idl` 3.86.0 (the surface in `scripts/bindings/web-surface.json`): DOM events, messaging, streams, files, encoding, compression, URL, fetch, Web Crypto, performance, timers, console, `WebAssembly`. Mapping (docs/JS_BINDINGS.md, "Standard bindings"): interfaces are handle structures over `Value`, Promise results `Async`, nullable values `Option`, dictionaries structures, unions inductives, callbacks `X.ofFn`/`X.ofSyncFn`. Example: `let res ← fetch (.usvString "https://example.com")`, `SubtleCrypto.digest (self : SubtleCrypto) (algorithm : AlgorithmIdentifier) (data : ByteArray) : Async ByteArray`. | decided, pending sign-off |
| 0.3-2 | `Lasm.JS.Web.Browser` (the browser tier) | The same generator and source, surface `scripts/bindings/browser-surface.json` (`scripts/bindings/web-browser.mjs`): `Lasm.JS.Web.Dom`, `Html`, `Css`, `Geometry`, `UiEvents`, `Canvas`, `WebSocket`, plus all of tier 1. Replaced `Lasm.Web` in 0.7.0 (A51). | decided, pending sign-off |
| 0.3-3 | `Lasm.JS.Web.Support` | Hand-written helpers the generated code calls, all public: `Record α`, `Support.optional`, `Support.args`, `Support.fields`, `Support.arrayBufferBytes`, `Support.typedArray`, `Support.getGlobal`, …. Open: whether they stay public or move to an internal namespace. | open |
| 0.3-4 | Generated-binding mapping rules (all tiers) | Overload names (`serve`, `serveWithOptions`), callback type names, number typing, checked downcasts, and the reviewed override table Jordan decided on 2026-11-16. A9–A12. | open |
| 0.3-5 | `Request`/`Response` conversion helper | Every server converts by hand (about 20 lines, as the `fetch` template's `serveNode` does). A13. | open |
| 0.3-6 | Generated binding modules compiled on first import | `Lasm.JS.Web.*`, `Lasm.JS.Node.*`, `Lasm.JS.Deno.*`, `Lasm.JS.Bun.*` and `Lasm.JS.Cloudflare.*`: a module of these namespaces that is not in `libraryModules` ships as source only. The build compiles it into the managed Lean prefix the first time a program imports it, as `lasm editor` does for a project's imports, with the modules it imports, resolved from the sources (src/lazy-library.mjs). It prints `[lasm] Compiling Lasm.JS.Web.IndexedDB (first use)…` and a total, and runs independent modules in parallel (up to half the cores, and one per 3 GB of memory). Outputs are written to a temporary file and renamed. They carry a stamp with their source identity and output hashes, which the tool cache's verification accepts. Why: the whole generated platform is about 300 MB compiled. Committing that to git on every regeneration, and shipping it in npm (483 → ~800 MB), is not acceptable (main, for Jordan, 2026-11-16). This pulls a slice of milestone 3.2 forward for the generated bindings only. No new flags. Rejected: shipping everything prebuilt (size), and a separate cache directory on `LEAN_PATH` (Lean resolves the `Lasm` package from a single root). PR #313. | decided, pending sign-off |
| 0.3-7 | Editor support for modules compiled on first import | **Open, must land within Stage 0.** Opening an editor on a file that imports a generated module no build or `lasm editor` has compiled yet shows Lean's missing-`.olean` error. Requirement: the editor compiles the module on demand, or at least says "run `npx lasm editor`". Direction (main, 2026-11-16): a Lake package for the library, so the editor's Lake builds a missing module itself; its own PR after the whole-platform PR. | open |
