# Lasm 0.3.6

A fix release for Vercel Edge, found while running Conduit on every platform.
Upgrade with `npm install -D @lasm/cli@0.3.6`. Nothing else changes in how
programs build or run.

## Vercel Edge (`--target vercel-edge`)

- **Deploys from a clean checkout.** Vercel looks for `api/` functions before
  it runs the build command, so the `api/lasm.mjs` that the build writes (and
  `lasm init --deploy vercel-edge` gitignores) was not deployed: `vercel build`
  finished with no function. The build now also writes the function in Vercel's
  Build Output API (`.vercel/output/functions/api/lasm.func`, with the
  production npm packages, and `.vercel/output/config.json` routing every path
  to it), as `--target vercel` already does.
- **Compressed files.** Vercel's edge runtime drops a response's
  `Content-Encoding` (Vercel compresses responses itself), so the Brotli copies
  that `Lasm.Fetch.Assets` serves arrived unlabelled and a browser app served
  this way did not start. The function now hides `Accept-Encoding` from the
  handler, so it sends files uncompressed.

## CI

- `workers.yml` runs `vercel build` from a tree without the generated function,
  with the build in `vercel.json`, and bundles a copy of the function alone.
- The candidate README test no longer depends on the README's first heading.
