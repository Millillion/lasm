# Draft: publishing `@lasm/cli` 0.1.0 (Phase 5.4)

**Status: DRAFT, awaiting the user's approval. Nothing here has been run.** No npm
package, git tag or GitHub release exists for 0.1.0. Phase 5.3 (release gate)
prepared this page; the evidence is in [PLAN.md](../PLAN.md) (5.3) and
[PROGRESS.md](../PROGRESS.md).

## What would be published

The accepted gate candidate, repackaged by
[`scripts/npm-dist/build-all.mjs`](../../scripts/npm-dist/build-all.mjs) without
changing its code:

- **Candidate:** `CANDIDATE_VERSION` (source `SOURCE`, SHA-256 `SHA256`, draft
  release `node-linux-candidate-RUN`).
- **`@lasm/cli@0.1.0`** (bin `lasm`): the candidate with `name` `@lasm/cli`,
  `version` `0.1.0`, `private` removed, `license` `MIT` plus the repository's
  `LICENSE`, and `src/npm-tools.json` pinning every tool package exactly. About 65 MB
  compressed, 365 MB unpacked (mostly the Wasm Lean runtime archives).
- **Tool packages** (one upstream-verified archive each, no code, no install scripts;
  versions follow the immutable release that published the archive):
  - required: `@lasm/lean-core-init`, `@lasm/lean-core-std` (`4.35.0-lasm.1`),
    `@lasm/emscripten-shared` (`6.0.9-lasm.1`);
  - optional, per platform (`linux-x64`, `linux-arm64`, `darwin-x64`, `darwin-arm64`,
    `win32-x64`): `@lasm/lean-<platform>` (`4.35.0-lasm.1`),
    `@lasm/emscripten-<platform>` (`6.0.9-lasm.1`);
  - fetched on demand with `npm pack`: `@lasm/lean-ext-meta`, `-ext-elab`, `-ext-rest`
    (`4.35.0-lasm.1`), `@lasm/git-<platform>` (`2.53.0-dugite.4`, Git from
    desktop/dugite-native, GPL-2.0).
  - Not packaged for npm: the C tier (Lean's clang and C library headers for Lake
    projects with C code). It is always downloaded from the `lean-4.35.0-c-v1`
    GitHub release, also under `LASM_ARTIFACT_SOURCE=auto`.

## Decisions for the user

1. **Licence of `@lasm/cli`.** The packed candidate says `UNLICENSED`
   (`scripts/package-node-release.mjs`); the repository `LICENSE` is MIT. Proposed:
   publish as MIT (`--license MIT`, below).
2. **Tool packages on npm or CLI only.**
   - *A (proposed, the tested design):* publish the 21 tool packages and the CLI.
     `npm install @lasm/cli` then brings Lean and the build tools through npm (about
     340 MB on Linux x64), honouring the user's registry, proxy and cache.
   - *B:* publish only `@lasm/cli` with its tool pins removed; every tool is
     downloaded from GitHub releases on the first build (the path every acceptance
     run uses today). Needs a packaging change and its own loopback check.
3. **Git redistribution** (option A): the `@lasm/git-*` packages republish
   dugite-native's Git binaries (GPL-2.0) with links to upstream source rather
   than shipping it. Alternative: build with `--no-git`, and Lake projects keep
   downloading Git from dugite-native.
4. **Account security:** publish from the `lastmjs` account with 2FA for writes on
   the `lasm` organization. npm provenance (`--provenance`) needs a CI publish
   (trusted publishing), which this plan does not use.
5. **Dist-tag:** `latest` for `@lasm/cli@0.1.0` (0.x already signals an early
   release). Tool packages have prerelease-style versions, which npm 11 only
   publishes with an explicit `--tag`; they use `--tag latest` as well, since the
   CLI pins exact versions and nobody installs them by tag.

## Commands (run by the user, from the repository root on Linux x64)

```sh
# 0. The exact accepted candidate
mkdir -p .work/release-0.1.0 && cd .work/release-0.1.0
gh release download node-linux-candidate-RUN --repo Millillion/lasm --pattern '*.tgz'
echo "SHA256  lasm-compiler-CANDIDATE_VERSION.tgz" | sha256sum -c -
cd ../..

# 1. Build every package deterministically (Node 26.12.1, npm 11.x; resource-guarded)
node scripts/npm-dist/build-all.mjs --base .work/release-0.1.0/lasm-compiler-CANDIDATE_VERSION.tgz \
  --out .work/release-0.1.0/npm --version 0.1.0 --license MIT --memory-mib 2048
# Compare with the CI loopback run of the same inputs (run NPM_DIST_RUN): every
# tool package's integrity in npm-dist.json must match; the CLI's too on Linux.
node -e "const r=require('./.work/release-0.1.0/npm/npm-dist.json');console.log(r.main);for(const p of r.packages)console.log(p.name,p.version,p.integrity)"

# 2. Log in (interactive; 2FA)
npm login
npm whoami        # lastmjs
npm org ls lasm   # lastmjs is an owner

# 3. Tool packages first (the CLI pins them), then the CLI
D=.work/release-0.1.0/npm
for f in $(node -p "require('./$D/npm-dist.json').packages.map(p=>p.filename).join(' ')"); do
  npm publish "$D/packages/$f" --access public --tag latest
done
npm publish "$D/packages/$(node -p "require('./$D/npm-dist.json').main.filename")" --access public --tag latest

# 4. Verify from the public registry in an empty directory
npm view @lasm/cli@0.1.0 dist.integrity dist-tags
cd "$(mktemp -d)" && npx --yes @lasm/cli@0.1.0 init app && cd app && npm install && npm run dev -- Ada

# 5. Tag the source of the candidate and attach the notes (after the publish)
git tag -a v0.1.0 SOURCE -m "Lasm 0.1.0 (@lasm/cli)" && git push origin v0.1.0
gh release create v0.1.0 --repo Millillion/lasm --title "Lasm 0.1.0" --notes-file docs/release/0.1.0-notes.md
```

All tarballs are written to `packages/` and named in `npm-dist.json` (the CLI's is
`lasm-cli-0.1.0.tgz`); check the list before step 3.
`npm publish` cannot be undone after 72 hours, and a published version number can
never be reused; if a step fails half-way, publish the remaining packages, never
re-publish a version.
