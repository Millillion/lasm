# Lasm 0.1.0 launch gate

**Result: passed.** Zero regressions against Phase 3 and `.58` in the upstream
runtime-capable suite and the ecosystem projects on all five targets. Three
back-to-back cold installations passed, as did server robustness, release
benchmarks and the npm rehearsal. Every non-pass is classified below; none is a Lasm failure.
Machine-readable record: [lasm-0.1.0-launch-gate-2026-10-25.json](../evidence/lasm-0.1.0-launch-gate-2026-10-25.json).
Decisions taken while the user was away: [DECISIONS.md](../DECISIONS.md).

## Benchmarks (release-benchmarks.yml, [40122614514](https://github.com/Millillion/lasm/actions/runs/40122614514), all five platforms)

[docs/BENCHMARKS.md](../BENCHMARKS.md) and
`docs/benchmarks/history/0.1.0-experimental.40121836396.json`. Against `.58`:

| Metric (linux-x64 reference) | `.58` | 0.1.0 gate |
| --- | ---: | ---: |
| Clean build, trivial program | 44.5 s | 5.0 s |
| Clean build, Hono app | 67.8 s | 9.0 s |
| First build incl. one-time tool download | 67.5 s | 38.6 s |
| Trivial program start to exit | 257 ms | 184 ms |
| Hono start to first response | 350 ms | 251 ms |
| `program.wasm`, trivial program | 1.07 MB | 0.55 MB |
| `dist/`, trivial program | 4.2 MB | 8.6 MB |
| Hono + Lean handler, throughput (ratio to plain Node) | 9,772 req/s (0.18×) | 14,349 req/s (0.17×) |
| Big numbers, 10,000-digit multiplication / division / toString (new) | — | 0.98 ms / 1.90 ms / 105 ms |

Clean builds are 4–9× faster on every platform. Windows throughput is lower
than `.58` in absolute terms, but the runner changed (plain Node's own
throughput halved on it), and the same-runner ratios improved. `dist/` for
the trivial program grew by about 4.5 MB on every platform while
`program.wasm` halved: Phase 6 added the musl builds of koffi and Lasm's native
helpers to every deployment, an accepted trade-off.
