# Lean models of Lasm's JavaScript and C

Milestone M4 of [docs/proposals/IRREDUCIBLE.md](../docs/proposals/IRREDUCIBLE.md)
ends when every JavaScript and C module that ships has a Lean model or a
stated reason why it needs none. This is that inventory, generated from
[models.json](models.json) and checked by `node scripts/models.mjs` on every
pull request (through `test/models-inventory.test.mjs`): every tracked file
under `bin/`, `native/`, `src/` and `library/c/` has an entry, every model
and model differential named exists and names the module, and this table is
current (`--write` rewrites it).

- **Modelled**: the module's logic has a Lean model, mirroring it function
  for function, and a model differential runs the model and the shipped code
  on the same inputs in CI. What it does beyond the model is stated.
- **Pending**: a model is still due (the reason says what for; models that
  exist for part of it are listed).
- **Exempt**: no model of its own, and why. The kinds:
  - `runtime`: Lean's runtime primitives on a host (files, clocks, sockets,
    processes): their meaning is native Lean's, and the differential tests
    run the same programs on native Lean and on every target
    ([docs/TESTING.md](../docs/TESTING.md#differential-testing));
  - `io`: orchestration of files, processes or the network (builds,
    downloads, the dev server), tested end to end;
  - `generated`: generated by a script from a description (the generator is
    what to check);
  - `data`: constants and configuration;
  - `deleting`: deleted with Lasm.Fetch.

How a module moves from pending to modelled:
[verification/cli/README.md](cli/README.md) (a model in
`verification/cli/Lasm/Cli/Model/`, its entry in
`test/models/cli-differential.mjs`, then the proofs).
