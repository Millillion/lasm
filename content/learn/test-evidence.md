### About

## Fuzzing at the boundaries

### Measured by CI

No scheduled fuzzing campaign on `main` yet. Until there is one, the corpus and the regressions are replayed on every merge (see the CI tiers above).

### About

Coverage-guided fuzzing feeds generated inputs to the code that reads input from outside, and fails on a crash, a hang or a broken property. Nightly campaigns run 10 minutes per target, and the Sunday campaign 60 minutes. The targets:

- `cli-arguments` (JavaScript (V8 block coverage)): the CLI's argument parser (src/cli-arguments.mjs and the init, dev and package parsers it calls).
- `serverless-http` (JavaScript (V8 block coverage)): the function platforms' HTTP boundary (src/serverless/): AWS Lambda's event → request mapping (API Gateway REST and HTTP API, function URLs, ALB, CloudFront) in lasm-lambda.mjs, and the cookie and body helpers of lasm-server.mjs every platform shim uses (joinCookies, parseSetCookie, azureReply, isTextual).
- `ui-patch` (JavaScript (V8 block coverage)): the Lasm.UI patch decoder (src/lasm-modules/ui-dom.mjs, the browser side of library/Lasm/UI/Encode.lean) against happy-dom.
- `lean-fetch-request` (libFuzzer): Lasm.Fetch request parsing as Node's host builds requests (path, query, cookies, Host)
- `lean-rpc` (libFuzzer): Lasm.RPC request and response decoding, and Lean's JSON round trip
- `wasi-cgi` (libFuzzer): the WASI C host's CGI request and response (src/wasi/lasm_fetch_wasi.c), with ASan and UBSan

Details: [Fuzzing at the boundaries](../../docs/TESTING.md#fuzzing-at-the-boundaries).

### Measured by CI

No nightly simulation run on `main` yet. Until there is one, each app's pull-request workflow runs 30 fixed seeds.

### About

Each night, for Tandem, Ledger, Porter, the simulation runs the real app against a simulated network, clock and storage with injected faults: 20 minutes of random seeds with the normal fault mix, then 10 minutes with heavy faults.
